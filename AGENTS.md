# Repository instructions

Start with AI-START-HERE.md, then PROJECT_INDEX.md and the selected project's README/AGENTS.md.
Use docs/ai/PROJECT-STANDARD.md for project structure and README expectations.
This is a repository for code and related artifacts the user creates, not a chat-summary archive.
For backups, preserve code/scripts and original assets created during the work.
For third-party tools/mods and machine configuration, a README with sources and what was done
is sufficient; do not bulk-copy downloads, installations or every file.
Existing research/history folders remain as imported; do not add one folder per conversation.
Keep actual source/build/config/test files accessible, with backups clearly separated.
Commit task changes on a non-main branch; read-only tasks require no commit.
Never modify or merge into main/master unless
the user specifically changes that instruction. Preserve unrelated user changes.
Use this repository as the source location. Installed programs and services are separate deployments.
A request to organize or back up projects does not authorize running installers, changing startup,
restarting services, applying EDID overrides, modifying saves, or switching displays.
Preserve provenance: existing source, extracted historical commands, new reusable adaptations,
third-party software, private data, and unverified research are different things.
Never infer success from an old command's exit code or from a copied binary.
Do not commit local-private/, credentials, pairing databases, raw personal exports, game saves,
crash dumps, or raw account history. No push is implied by a local commit.
Keep hardware/app IDs configurable in new work. Never hardcode versioned WindowsApps paths.
Do not run archived startup scripts or replay historical session commands automatically.
Use each project's current documentation for hardware-specific state and pending implementation.
